# 任务初始化（Phase 0）：任务库之外的那一层

> 2026-10-11。对应用户给的《Phase 0 任务初始化指南》四步。第一轮**原任务库一个字没动**；第二轮按用户的四条决定改了题面
> （任务库 2.6 → **2.7**，见 missions_v2 开头）。`missions.FAMILIES`、评分契约、task_id 全部照旧。
> 新加的是 `artquest/taskspace/`——一个 Agent 读的「资料库」，把每道题的来源、蓝图、属性、材料和检查结果连起来。
> 生成的报告在 `docs/任务空间/README.md`（生成物，不进仓库；本地跑 `tools/taskspace_report.py` 就有）。

```
.venv/bin/python tools/taskspace_report.py     # 重新生成 docs/任务空间/（README.md + taskspace.json + frames/）
.venv/bin/python -m unittest tests.test_taskspace
```

Agent 侧入口：

```python
from artquest.taskspace import initialize
ts = initialize()            # 不选题、不评学生、不改库
ts["candidates"][0]          # 每道 v2 题：copy / fixed / free / dims(带理由与成立条件) / materials / source_relations / issues / status
ts["gaps"]                   # 课标里有、库里没有的操作
```

## 两条边界（整个包都按这个写）

- **任务属性描述任务，KidsArtBench 九维评价作品。** 候选里的 `dims` 只说「这道题可能提供哪种观察机会、在什么条件下成立、
  孩子能不能合理地绕开它（`bypass`）」。不是题目分数，不是学生能力，也不改 `FAMILIES` 里的 rubric（九个维度全评那条不变量照旧）。
- **来源关系 ≠ 检查结果。** `原文明确规定 / 基于来源改编 / 项目新增条件` 记设计从哪来；`找到支持 / 存在矛盾 / 依据不足` 记自动检查看到了什么。
  「项目新增条件」必须写用途，没有用途检查就拦（R1）。

## Step 1 · 来源 → 蓝图（`sources.py` / `blueprints.py`）

**课标真的核了。** 教育科学出版社那份 PDF 是扫描件、没有文字层，我把美术部分（正文 49–68 页）逐页渲染成图看了一遍，
转录了 36 条片段，正文页与 PDF 页分开记（偏移 7，正文 56 = PDF 63，和你说的一致）。
转录是人工的，**还没有人抽查**（第 12 项）。KidsArtBench 用本机 PDF 的 Table 1 核了九维定义。

**第二轮补上的来源（用户定位、我本机下载后 pdftotext 核对，2026-10-11）：**

|---|---|---|---|

现在库里引用的片段**全部有原文**，没有「待录入」。

**蓝图一家族一条（BP_M1…BP_M9，BP_M0 是 legacy 基线）**，每条回答六问（学段 / 目标 / 操作 / 输入 / 产出 / 不能改的条件）
外加自由空间和负担组成（比较几个方案、空间关系、读文字、修改已有内容——没有难度数字）。
学段：先沿用来源学段，再写「拟适用」到本项目的 simple / full 两版并给理由。

**覆盖与缺口**（报告 §2.x）：五种操作里，库里只有「观察与表现」和「个人表达」+ M4 的「有目的的设计（物品改造）」。
课标里有、库里没有的四个缺口都留着没填：

| 缺口 | 为什么没有 | 要先做什么 |
|---|---|---|
| 多样化构想（提出各种构想，课标 p55/p61；PISA） | 没有家族要多个方案；产品一局只能存一幅 | `multi_sketch_output` |
| 评价与改进（草图改进，p55/p62；PISA DT200Q02） | 没有「起始作品」材料，起始画面上的东西不能移动 | `editable_starting_artwork` / `movable_objects` |

| 观察自然对象的形状 / 色彩 / 肌理（p49） | M1/M2 都是人造场景或静物 | 新参考图材料规格 |

## Step 2 · 候选（`candidates.py`）

80 道 v2 题每道一条候选：文案（带 sha，R7 守着和 `TASK_VERSION` 一致）、固定项、自由空间、来源关系（蓝图的 + 题面自己的新增条件）、
九维关联（family 的 primary / secondary 翻译成「理由 + 成立条件 + 可绕开」）、材料规格、相对本家族第一道锚定题「改变了什么 / 保持了什么」。
「无参考图」是明确配置 `materials.NONE`，不是漏字段。

## Step 3 · 检查（`checks.py`）

规则检查 R1–R15 和语义检查 S1–S6 分开记 `judge`；语义层默认是离线启发式（反向提取：只给文案 + 材料说明，让它说学生实际要做什么），
可以插模型（`initialize(semantic_judge=fn)`），但规则判定永远不被模型覆盖。
每个问题带：出现在哪里 / 违反哪条 / 依据 / 最小修改 / 改后重查什么。

反例（`mutations()`）：把单幅改成两种方案、在自由设计里塞「必须画一本打开的书」、新增条件不写用途、引用不存在的片段、
产出超出能力、primary 关联到可绕开的维度、文案要看图却没配图——七个都被抓到（`tests/test_taskspace.py`）。

## Step 4 · 材料（`materials.py`）

每份材料先定用途（正式观察参考 / 供改造的物品图 / 供改色的中性场景 / 画布上的碎片），再写必须出现的对象与关系、不该出现的、可变的。
视觉问题按依赖排（对象存在 → 可辨识 → 关系 → 显示帧裁切后仍清楚），前提失败后面的项「阻塞」，不用平均分盖掉。
没接视觉模型，所以需要看图的项全是「无法判断」——但**显示帧真的裁出来了**（`docs/任务空间/frames/`，按 `style.css` 的 2:1 桌面缩略图和约 2.8:1 手机缩略图）。
能用像素量的量了：尺寸、白底、物体占高 / 占宽、平均饱和度、裁切损失。

量出来的两个问题：

- **m4_bicycle 不符合**：非白像素占高 92%（规格 ≤ 90%）。缩略图裁掉上下各 14%，两个轮子的底被切掉——「整车不出框」在孩子实际看到的那一帧不成立。
  （另六张 M4 在 55–90% 内。）
- **m2_scene_e 手机缩略图**（人工看帧）：笔筒底部被裁掉，「折叠尺压住笔筒底部」这处遮挡在那一帧里只剩一半。桌面帧没问题。

M6 五张的饱和度：a 0.16 最中性，b 0.49 擦着上限（ART_LIST 里已经写过「重画压低一点」）。

## 视觉判断器（`vision.py`，代码就位，**没实测**）

ecnu-plus 官方文档声明支持图片（`image_url` + base64），`artquest.llm` 的 openai 通路本来就会把图片块转成 data URL。
`VisualJudge` 把 check_material 里需要看图的问题交给模型，状态分开记：请求失败 / 解析失败另列在 `last_errors`，
**不映射成「无法判断」**。`probe()` 先用两张左右相反的图、同一个问题确认答案随图变化。

| 层次 | 状态 |
|---|---|
| 官方是否声明支持图片 | 已确认（用户核的文档） |
| 本项目实际请求是否成功传图并得到回答 | **未实测**——key 在服务器，用户自己跑 `tools/try_visual_judge.py` |
| 能否可靠判断对象与遮挡 | 尚未验证 |
