# 彩绘冒险 · 第一次试点测试流程

**版本** 2026-10-01 · **形式** 学校机房，电脑网页版 · **地址** https://art.ddhulu.cn

这次试点的目的不是收正式数据，是把三件事跑通：孩子在电脑上用鼠标能不能顺利画完一个任务；一节课的时间够不够；老师端打分顺不顺。正式研究的对照组、任务平衡这些留到第二轮。

---

## 1. 人和物

| 角色 | 人数 | 做什么 |
|---|---|---|
| 主试（研究员） | 1 | 开场说明、看服务器、处理故障、记录时间 |
| 美术老师 | 1 | 课堂组织、按脚本引导、课后打分 |
| 助手 | 每 12 台电脑 1 人 | 走动帮忙解决登录和工具问题，不帮画 |
| 学生 | 建议 12 到 24 人 | 6 到 14 岁，同一个班最好 |

物品：

- 每人一台电脑，带鼠标。有手绘板更好，没有也行。
- 班级名册一张，纸质，写每个孩子的**代号**和四位密码，课后由老师保管，不进电脑。
- 监护人同意书回执，课前收齐。
- 一台 iPad 装了 TestFlight 版，给主试对照用，不发给学生。
- 计时器。

## 2. 机房要提前一天准备好

每台电脑逐一检查，不要抽查：

1. 浏览器用 **Chrome 或 Edge**，版本一年以内。不用 IE、不用 360 极速以外的国产浏览器。
2. 打开 https://art.ddhulu.cn 能看到「彩绘冒险」门口，点「跳过」能进到地图。这一步同时验证了网络没拦、证书正常。
3. 屏幕分辨率 1366×768 以上。浏览器缩放设回 100%（Ctrl+0）。
4. **每台电脑一个带代号的桌面快捷方式**，网址是 `https://art.ddhulu.cn/?pid=A07`，`A07` 换成这台电脑上孩子的代号。代号跟电脑走，名册上写清哪台电脑是谁。孩子只要双击，不用打字。
5. 机房的上网行为管理如果拦了 `art.ddhulu.cn` 或 `*.ddhulu.cn`，请信息老师加白名单。
6. 主试在服务器上确认三样：

```
ssh artquest
cat ~/artquest/data/study.json          # 第 3 节的配置
grep ANTHROPIC ~/artquest/.env          # 要真 AI 反馈就得有这一行
journalctl --user -u artquest -n 20     # 服务在跑
```

7. 用一台电脑和那台 iPad 各完整画一遍，确认老师端 /teacher 能看到这两件。画完把这两件的账号从老师端记下来，课后不要算进数据。

## 3. 本次的条件设置

试点所有孩子一个条件，不分组。服务器 `~/artquest/data/study.json` 设成：

```json
{
  "active": true,
  "study_id": "pilot1",
  "order": "latin",
  "condition": {
    "ui": "full",
    "reference_allowed": true,
    "undo_allowed": true,
    "zoom_allowed": true,
    "questionnaire": true,
    "feedback_source": "ai",
    "dialogue_mode": "on_demand",
    "growth_display": "full",
    "gallery_display": "after_submit",
    "share_consent": true,
    "time_limit_sec": null
  },
  "protocol": {
    "protocol_id": "pilot1",
    "required_families": ["M1", "M3", "M9"],
    "randomization_rule": "latin",
    "prompt_style_rule": "balanced"
  }
}
```

说明：

- 三个家族，每个孩子按拉丁方拿到不同的题。一节课做不完三个没关系，做几个算几个，顺序有记录。
- `share_consent: true` 只是允许孩子自己选「挂上墙」，不是替他同意。没勾「作品可公开」的班级设成 `false`。
- 真 AI 反馈要在服务器 `~/artquest/.env` 里改三行，然后 `systemctl --user restart artquest`：

```
ARTQUEST_SCORER=auto
ARTQUEST_FEEDBACK=auto
ANTHROPIC_API_KEY=sk-ant-...
```

  现在服务器上写的是 `heuristic` / `template`，没有 key：孩子也能跑完流程，但反馈是模板，不看画。试点用哪一种，课前定。
- `study.json` 改完不用重启，每次请求都重读；`.env` 改了要重启。

## 4. 代号和账号：不用真名

代号格式 `班级字母 + 两位数`，比如 `A07`。它由第 2 节那个快捷方式里的 `?pid=A07` 交给服务器，用来决定这个孩子拿到哪几道题、什么顺序。**没有代号的电脑，所有孩子会拿到同一个顺序**，所以快捷方式一台都不能漏。

进去之后孩子还要注册一个账号：名字就填同一个代号 `A07`，密码四位数，主试提前印在名册上。账号让画跟着人走，换台电脑登录还在。

服务器上只有代号，代号和真名的对照只在老师手里那张纸上。删数据、退出研究都按代号找。

页面顶部会有一条红色标签的细条写着「pilot1 · 被试 A07」，那是研究员看的，告诉孩子不用管。

登录后的第一次导览会指着按钮讲一遍，孩子自己点就行，不用老师讲。

## 5. 一节课怎么排（40 分钟）

| 时间 | 事 | 谁 |
|---|---|---|
| 0–3 分 | 开场：这是什么、要做什么、可以随时不做 | 主试 |
| 3–8 分 | 每人打开网址 → 注册（代号 + 密码）→ 看导览 → 到地图 | 助手走动 |
| 8–22 分 | **第一个任务**：地图上点亮着的那一关 → 心愿 → 画 → 画好了 → 看反馈 → 改一改或不改 → 宝藏 | 老师引导 |
| 22–35 分 | **第二个任务**，同上。快的孩子可以做第三个 | 老师引导 |
| 35–38 分 | 问卷（画完自动出现，三道题，30 秒） | 自动 |
| 38–40 分 | 收尾：谢谢，下周会看到老师的评语 | 老师 |

有的题带 9 分钟时限，到时自动交卷，但屏幕上不显示倒计时，孩子不知道在计时。老师也不要提醒时间。

两个任务是稳妥的量。第一次试点如果发现第一个任务就用了 20 分钟，第二个任务砍掉，把时间记下来。

主试全程记三个时间点：全班登录完、第一个任务全班交完、下课时做到第几关。这是本次试点最重要的数据。

## 6. 老师和助手的引导脚本

**开场，主试说**（大意，用自己的话）：

> 今天我们试一个新的画画软件。每人一个代号，就是纸上写的这个。画什么都可以，画得像不像都可以，没有分数，没有对错。画完软件会给你说几句话，你可以照它说的改一改，也可以不改。中间想停下来可以随时举手，没有关系。

**可以做的**：

- 帮孩子找按钮、换颜色、撤销、放大缩小。
- 孩子问「我可以画 X 吗」，答「可以，你决定」。
- 孩子说「不知道画什么」，答「先看一遍题目，随便画一个开头，画着画着就有了」。再不行让他点右上角看参考图。
- 孩子问「这样对吗」，答「你觉得对就对」。

**不做的**：

- 不评价画得好不好，一句都不说，包括「真棒」。
- 不告诉孩子画什么、怎么画、用什么颜色。
- 不代替孩子点「画好了」「改好了」。慢的孩子让他慢。
- 不读反馈给孩子听，除非孩子不识字。识字的让他自己读。
- 孩子画出让人担心的内容，不在课堂上问，记下代号，课后告诉主试，按第 9 节处理。

**电脑上和 iPad 不一样的地方**，助手知道就行：

- 鼠标画线比手指粗糙，这是正常的，不用道歉。
- 没有压感，粗细靠工具栏里的笔粗细。
- 画布用鼠标滚轮缩放，按住空格拖动画布。孩子一般用不到。
- 浏览器窗口不要中途最大化或缩放，会让画布重新排版。全屏用 F11，开场时统一按。

## 7. 课后当天，主试做

```
ssh artquest
ls ~/artquest/data/sessions | wc -l                          # 应该 ≈ 人数 × 任务数 + 2 件测试
cd ~/artquest && .venv/bin/python tools/check_json.py         # 数据文件都能打开
```

然后从老师端 https://art.ddhulu.cn/teacher 用研究员令牌登录，看每件作品都有最终图和过程图。把课前那两件测试作品记下来。

把 `data/` 整个目录备份一份：

```
rsync -az artquest:artquest/data/ ~/artquest-backup/pilot1-$(date +%F)/
```

## 8. 老师打分，一周内

- 老师从 https://art.ddhulu.cn/teacher 登录，邀请码向主试要。
- 每件作品要 3 位老师各评一次。打分列表里只显示还没评满、自己也没评过的，评满的自动消失。
- 每件：最终图九个维度打分加一段评语，三张过程图至少写一条短评。评分参考在左栏。
- 老师第一次打分前，主试陪着评两件，把「评分参考」过一遍。
- 主试从研究员接口看进度：

```
curl -H "Authorization: Bearer <研究员令牌>" https://art.ddhulu.cn/api/v1/teacher/progress
```

## 9. 出现让人担心的画面

孩子可能画出暴力、自伤或家庭问题相关的内容。约定：

1. 课堂上不追问、不制止，让他画完。
2. 老师课后把代号告诉主试。
3. 主试和老师一起看这一幅，决定是否需要告诉班主任或心理老师。学校有自己的流程就走学校的。
4. 这一幅在数据集里标记，不进公开数据集，不进画廊。
5. 记录一行：日期、代号、处理方式。不记内容细节。

## 10. 试点要回答的问题

结束后主试填一张表，每项一句话：

| 问题 | 怎么看 |
|---|---|
| 一个任务平均用了几分钟 | 服务器 sessions 里的 duration，加上现场记的时间点 |
| 有多少孩子做到了第二个任务 | sessions 数 ÷ 人数 |
| 有多少孩子在反馈之后改了 | `revised` 为真的比例 |
| 鼠标画画有没有卡住谁 | 助手记录的求助次数和内容 |
| 反馈孩子看得懂吗 | 现场观察，有没有孩子问「这是什么意思」 |
| 问卷答完了吗 | 每个 session 有没有 questionnaire |
| 老师评一件要几分钟 | 老师端每条评分带 `t_ms` |
| 三位老师的一致性 | 导出后算 |
| 服务器扛得住吗 | 课上有没有报错、`journalctl` 里有没有 5xx |

导出：

```
cd ~/artquest && .venv/bin/python tools/export_dataset.py --out export/pilot1
```

## 11. 退出和删除

家长或孩子要退出，主试在服务器上：

```
cd ~/artquest && .venv/bin/python tools/withdraw.py A07                                   # 先看会删什么
cd ~/artquest && .venv/bin/python tools/withdraw.py A07 --confirm A07 --receipt withdrawals/A07.json
```

删的是这个代号的全部 session，回执只记删了几件、什么时候。名册上把这一行划掉。
