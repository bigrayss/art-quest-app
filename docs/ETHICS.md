# 儿童研究数据：身份隔离、同意与撤回

研究对象是 8–14 岁的孩子，所以数据层从第一天就要按"以后会公开、会被别人重分析"来设计，
而不是"先收着，回头再脱敏"。回头脱敏几乎总是做不干净。

## 1. 身份隔离：真实身份不进研究系统

```
真实身份（姓名、班级、联系方式、监护人信息）
        │   ← 隔离在另一套系统 / 一张离线名单
        ▼
participant_id（P007 这种代号）
        ▼
研究数据（sessions / strokes / events / 作品）
```

App 这一侧的约束，已经落到代码里：

- session 只存两个匿名 id：设备自动生成的 `anon_id` + 研究员分配的 `participant_id`；
- 名册 `participants.json` 只有「代号 → 序号」，用于平衡拉丁方，**不含真名**；
- 评分者、标注者同样只用 `rater_id` 伪匿名编号。

**代号与真实身份的对照表不要放进这个仓库，也不要放进研究服务器。**

`participant.label` 是一个遗留自由文本字段，UI 上写着"不要写真名"。做正式研究前建议直接停用它。

## 2. 收集之前要备好的东西

- **监护人知情同意（parental consent）**：说明收什么（作品、笔触轨迹、操作日志、1–5 自评）、
  为什么收、存多久、谁能看到、会不会公开。
- **儿童本人同意（child assent）**：用孩子能懂的话，单独讲一遍，且**可以随时说不**。
- **数据保留周期**：写明原始数据保留多久、之后如何处置。
- **图片公开许可**：儿童作品是否可以出现在论文、数据集、演示里，要**单独**勾选——
  同意参与研究不等于同意作品被公开。
- **敏感内容审核**：孩子可能画出令人担心的内容。发布任何数据集之前必须有人逐张看过，
  并事先约定好发现此类内容时的处理流程（通知谁、如何记录、是否上报）。

## 3. 撤回

同意可以被收回。这是整个项目里**唯一**"真删"的地方——别处的原则是「只标记，不删数据」
（QC 失败是标记，被撤销的笔仍留在日志里），但撤回不同：数据必须真的消失，而不是被标成可忽略。

```bash
python3 tools/withdraw.py P007                  # dry run，先看会删掉什么
python3 tools/withdraw.py P007 --confirm P007 --receipt withdrawals/P007.json
```

- 该被试的所有 session 目录整个删除（作品、日志、自评、反馈、评分）；
- 名册里代号被标为 `withdrawn`，但**序号保留占位**——否则后来的被试会继承他的任务顺序，
  在分析里悄悄变成他；
- 回执只记「删了几个 session、哪些 id、什么时候」，**不留任何内容**，用于审计。

已经导出过的数据集副本、以及已经发表的内容，需要另行按同意书里写明的方式处理——
工具只能管本地这一份。

## 4. 公开数据集之前

- [ ] 逐张过一遍作品，敏感内容按预案处理
- [ ] 确认每个被试都有「作品可公开」这一项的许可
- [ ] 移除 `participant.label`、自由文本自评里可能出现的人名/校名
- [ ] 检查 `device` 字段（UA、屏幕尺寸、时区）在你的场景下是否构成可识别信息
- [ ] 确认已撤回的被试不在导出里（`tools/export_dataset.py` 读的是当前目录，撤回后重新导出）

OECD 关于大规模教育测评中 process data 的建议是：过程日志不该"顺手收"，
而应该 **by design** 地定义采集目的、验证方式、伦理与公平性——上面这几条就是这个意思的落地。
